### Added

- The lock step: requests a lock from a Jenkins lockable-resources server
  (remote API, delegated mode), waits in the server's queue, sets the
  `lockEnvVars` as environment variables and the outputs `lock-id`, `state`,
  `acquired`, `resources`, `env-vars`. Every `lock()` selector is an input
  (`resource`, `label`, `group`, `quantity`, `variable`, `inverse-precedence`,
  `resource-select-strategy`, `skip-if-locked`, `extra`, `priority`,
  `timeout-for-allocate-resource`, `timeout-unit`, `reason`).
- The release sub-action (`/release`), required to free a lock. It refuses to
  release a lease that is already STALE and retries transient failures for
  about 60 s.
- A heartbeat process that keeps the lease alive between the lock step and
  the release step.
- The post step: never releases a held lock (a failure while holding leaves a
  STALE lease for an administrator to check); withdraws requests that were
  never handed over; fails the job when a held lock was not released.
- Server URL and user name from the `LOCKABLE_RESOURCES_SERVER_URL` and
  `LOCKABLE_RESOURCES_USERNAME` environment variables; the token only from the
  `token` input.
- Error messages with hints for the usual causes (wrong token, missing
  permission, unexposed resource, wrong context path, redirects).
- `dist/licenses.txt`: the notices of the third-party packages bundled into
  `dist/`, generated by the build.
